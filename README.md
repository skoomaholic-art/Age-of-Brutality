# Жестокий Век

Репозиторий настольной стратегической игры **«Жестокий Век»**.

## Текущая рабочая версия

**V5.7.2-DEV**

V5.7.1 сохранена как исторический baseline, но больше не считается прошедшей release gates: Game Master выявил критические дефекты prisoner/state/coverage. Новая разработка ведётся только через этот репозиторий.

## Source of truth

**GitHub `main` = единственный MASTER проекта.**

Рабочий цикл:

`ФИДБЭК → АНАЛИЗ → RULES/DATA/CARDS/ARENA/AI SYNC → COMMIT → QA → BUILD → файл пользователю «пощупать»`

Локальный файл, не отражённый в репозитории, не считается новой канонической версией.

## Системная цепочка

Каждое изменение проверяется по цепочке:

`ПРАВИЛА → MASTER GAME DATA → КАРТОЧКИ → КАРТА → ARENA → AI → GAME MASTER → ПЛЕЙТЕСТ → PRINT`

Числовое значение, условие или идентификатор, отличающийся между зависимыми источниками, считается ошибкой до явного решения проекта.

## Статус аудита

Полная стартовая инвентаризация V5.7.2-DEV: `docs/PROJECT_AUDIT.md`.

Подтверждённые открытые проблемы: `docs/KNOWN_ISSUES.md`.

Ключевые блокеры на старте:

- в Arena не реализован полный post-capture цикл;
- пленник не хранит захвативший Дом;
- смерть смешана со статусом `ПЛЕН`;
- старый фиксированный выкуп 3 конфликтует с подтверждённым `Требовать выкуп N`;
- семейные командиры не синхронизированы;
- `Айрельь` в MGD ломает связку с `Айрель` в остальных источниках;
- AI не выбирает династический союз;
- births/raids имеют нулевое coverage в текущем 100-seed диагностическом прогоне;
- topology JSON имеет неверную внутреннюю версию;
- полноценный print-ready package ещё не прошёл gates.

## Подтверждённая механика плена

После захвата персонажа победитель должен иметь четыре варианта:

1. **Отпустить пленника**
2. **Взять в плен**
3. **Требовать выкуп N**
4. **Казнить**

Диапазон/правило значения `N` пока отдельно не установлен и не должен молча заменяться старым фиксированным значением.

## Исторический QA

Game Master V1 на V5.7.1 прогнал 100 seeds 57001–57100: 100/100 партий структурно завершились на R6 без engine errors/invalid actions, но выявлены CRITICAL rules-completeness/state defects и недостаточное coverage некоторых механик. Поэтому этот прогон является диагностикой, а не сертификатом релиза.

## Репозиторий

Целевая структура:

- `rules/` — канонические правила и print export;
- `data/` — Master Game Data и нормализованные системные параметры;
- `cards/` — card source, print sheets и previews;
- `map/` — topology, visual source и print exports;
- `components/` — жетоны, планшеты, player aids;
- `arena/` — исходники и executable builds;
- `ai/` — профили и decision config;
- `game_master/` / `qa/` — валидаторы, regression, coverage, balance;
- `playtests/` — raw logs и reports;
- `docs/` — аудит, решения, known issues, BOM и print guide;
- `release/` — только package, прошедшие release gates.

## Release policy

Статусы: `DEV → ALPHA → BETA → RC → STABLE`.

`STABLE` разрешён только после прохождения всех release gates: Rules, Data, Cards, Map, Arena, AI, Game Master, Playtest, Coverage, Print, Rulebook и Components.

Не смешивать экспериментальную 30-ОП / `RULE_PENDING` ветку с активной шестираундовой линией без отдельного подтверждённого решения и полной синхронизации зависимостей.
