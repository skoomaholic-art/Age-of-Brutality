# Рабочий процесс проекта «Жестокий Век»

## Единственный источник истины

Репозиторий GitHub `skoomaholic-art/zhestokiy-vek` является единственным рабочим источником проекта.

Любые изменения правил, Master Game Data, карточек, Arena, AI, карты, плейтестов, аудита, QA и документации должны сначала фиксироваться в репозитории.

Файлы, отправленные пользователю в чат, являются только сборками для ручной проверки и не считаются отдельным источником истины.

## Обработка фидбэка

После получения фидбэка:

1. Проверить затронутую механику по цепочке `ПРАВИЛА → DATA → КАРТОЧКИ → ARENA → AI → ПЛЕЙТЕСТ`.
2. Внести согласованные изменения в соответствующие файлы репозитория.
3. Обновить связанные данные, документацию, changelog и QA-статус.
4. Зафиксировать изменения коммитом в GitHub.
5. Только после этого собрать пользовательский файл/билд для ручной проверки.
6. Переданный пользователю файл должен соответствовать зафиксированному состоянию репозитория.

## Что получает пользователь

По умолчанию пользователь получает только тот артефакт, который нужно проверить руками: Arena HTML, DOCX правил, XLSX данных/карточек, карту, ZIP билда или иной конкретный продукт.

Нет необходимости пересылать пользователю полный набор промежуточных исходников после каждого изменения, если он прямо этого не просит.

## Версионирование

Нельзя создавать локальную «актуальную» версию, которая не отражена в GitHub.

Новый файл для ручной проверки должен быть связан с текущей версией/коммитом репозитория. Если пользователь принимает или корректирует результат, следующий цикл снова начинается с обновления репозитория.

## Принцип

`ФИДБЭК → АНАЛИЗ → ИЗМЕНЕНИЕ В REPO → COMMIT → СБОРКА → ФАЙЛ ПОЛЬЗОВАТЕЛЮ → НОВЫЙ ФИДБЭК`
